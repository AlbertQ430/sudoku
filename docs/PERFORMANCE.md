# 性能报告

> 日期：2026-10-30
> 需求基线：SRS V1.4（题库化后，「生成」不再是运行时行为）
> 结论口径：只写实测数据；没有实测的明确标「待真机」。

## 1. 测试环境

| 项 | 值 |
|---|---|
| CPU | Intel Core i9-14900HX（32 线程） |
| 内存 | 16 GB |
| 系统 | Windows |
| Node | v26.13.0 |
| 数据 | 五档题库各 200 道，共 1000 道 |

> **注意**：这台机器的 CPU 属于 Intel 13/14 代「Raptor Lake 不稳定」受影响型号，
> 系统日志里已有 `WHEA-Logger` 可纠正硬件错误。基准数据可能受此影响而偏乐观或抖动，
> 但不影响量级判断（所有指标都远低于阈值）。

## 2. 引擎层实测

复现：`pnpm perf`

单位毫秒。JSON 解析 = 首次加载某难度题库；取题校验 = 运行期 `pickPuzzle` 做的那次唯一解复核。

| 难度 | 题数 | 平均提示 | 题库大小 | JSON 解析 | 取题校验 P50 | 取题校验 P95 | 求解 P50 | 求解 P95 | 评级 P95 |
|---|---|---|---|---|---|---|---|---|---|
| 入门 | 200 | 51.0 | 39.3 KB | 0.04 | 0.02 | 0.06 | 0.03 | 0.04 | 1.63 |
| 简单 | 200 | 27.2 | 39.3 KB | 0.03 | 0.05 | 0.32 | 0.05 | 0.21 | 9.89 |
| 中等 | 200 | 25.4 | 39.3 KB | 0.05 | 0.08 | 0.43 | 0.06 | 0.48 | 4.84 |
| 困难 | 200 | 24.8 | 39.3 KB | 0.04 | 0.07 | 0.40 | 0.05 | 0.26 | 21.82 |
| 专家 | 200 | 24.8 | 39.3 KB | 0.04 | 0.11 | 0.74 | 0.11 | 0.39 | **933.15** |

进程 RSS 约 70 MB（加载五档题库 + 跑完全部基准后）。

## 3. 关键结论

**1. 用户的等待时间已经可以忽略。**

从点击难度到棋盘出现，主要成本是网络加载那 39 KB 的题库分块（gzip 后约 15 KB）加一次 0.74 ms 的校验。之前运行时生成的路径已经整条移除。

**2. 难度评级是唯一的重活，而它只在构建期跑。**

专家档评级 P95 达到 **933 ms**，是入门档的 570 倍。这正是旧方案崩溃的根源——运行时生成要在浏览器里反复评级，专家档几次就把渲染进程拖垮。

题库化把这块开销整条移出用户路径：1000 道题在构建期评一次，之后永远不再评。

**3. 求解远快于要求。**

要求 P95 ≤ 1 秒（NFR-PERF-003），实测最慢档 0.48 ms。

## 5. 待真机验证的操作清单

这三项需要浏览器，脚本测不了。按顺序做即可：

### 5.1 首屏与体积（NFR-PERF-006）

```bash
pnpm build
pnpm preview
```

Chrome DevTools → Lighthouse → 勾选 Performance + Mobile，跑一次。

关注两个数：

- **FCP / LCP** ≤ 2.5 s（网络节流 Simulated Slow 4G）
- **Total byte weight** ≤ 500 KB gzip

已知基线（构建产物）：

| 文件 | 原始 | gzip |
|---|---|---|
| 主包 `index-*.js` | 340 KB | 110 KB |
| 题库（按需，单档） | 39 KB | 15 KB |
| 样式 | 14 KB | 3.7 KB |
| Worker | 47 KB | — |

首屏不加载任何题库，所以首访约 160 KB gzip。

### 5.2 内存（NFR-PERF-007）

DevTools → Performance monitor，连续开 30 局（每局点「再来一局」）。

看 `JS heap size` 曲线：只要不持续单调上升即可。题库缓存在第一次加载某难度后就不再增长，理论上是一条平线。

### 5.3 交互反馈（NFR-PERF-005）

DevTools → Performance → 录制 → 点一格、按一个数字 → 停止。

看 `Input` 到 `Paint` 之间的间隔，应 ≤ 50 ms。

## 6. 已知偏差

- 基准在 Node 里跑，V8 引擎与浏览器同为 JIT，量级可信；但浏览器还要处理 DOM 与样式，交互延迟会高于纯计算。
- 题库加载在 Node 里是同步 `readFileSync`，浏览器是网络请求 + 动态 import，真实耗时取决于网络。分块 gzip 后 15 KB，在 10 Mbps 下约 12 ms。
